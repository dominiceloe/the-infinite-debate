# Agent Reports Directory

This directory contains detailed reports generated by maintenance agents. All agents write their findings here for tracking, analysis, and continuous improvement.

**Created:** October 20, 2025
**Purpose:** Central repository for agent-generated quality assessments, test coverage reports, and persona audits

---

## Directory Structure

```
.reports/
├── debate-quality/          # Debate Quality Auditor reports
│   ├── debates/             # Individual debate audit reports
│   └── summaries/           # Aggregate quality analysis
├── test-coverage/           # Test Maintainer reports
│   ├── gaps/                # Coverage gap analyses
│   ├── progress/            # Coverage improvement tracking
│   └── quality/             # Test quality assessments
└── persona-quality/         # Persona Manager reports
    ├── validation/          # Persona validation reports
    ├── sync/                # Database sync reports
    └── scorecards/          # Individual persona quality scores
```

## Agent Reporting Standards

### File Naming Conventions

**Debate Quality Auditor:**
- Per-debate: `YYYY-MM-DD_HH-MM_{topic-slug}_{participant-slugs}.md`
- Summaries: `YYYY-MM_{description}.md`

**Test Maintainer:**
- Gap analysis: `YYYY-MM-DD_coverage-gap-{scope}.md`
- Progress: `YYYY-MM-DD_coverage-progress.md`
- Quality audit: `YYYY-MM-DD_test-quality-{module}.md`

**Persona Manager:**
- Validation: `YYYY-MM-DD_validation-report.md`
- Sync: `YYYY-MM-DD_sync-report.md`
- Scorecard: `{persona-slug}_YYYY-MM-DD.md`

### Report Quality Standards

All reports must include:
- **Executive Summary** - Key findings in 3-5 bullet points
- **Detailed Analysis** - Specific examples with quotes/code
- **Actionable Recommendations** - What to do next
- **Metrics** - Quantitative assessment where applicable

Reports should be:
- **Thoughtful** - Provide insights, not just data
- **Specific** - Include concrete examples
- **Actionable** - Clear next steps
- **Timestamped** - Track trends over time

## Usage

### For Contributors

**Reading Reports:**
```bash
# Latest debate quality summary
cat .reports/debate-quality/summaries/$(ls -t .reports/debate-quality/summaries/ | head -1)

# Latest coverage gap analysis
cat .reports/test-coverage/gaps/$(ls -t .reports/test-coverage/gaps/ | head -1)

# Specific persona scorecard
cat .reports/persona-quality/scorecards/socrates_*.md | tail -1
```

**Generating Reports:**
Agents automatically write reports when invoked:
```bash
# Triggers debate quality audit + report
"Run debate-quality-auditor with cross-tradition tests"

# Triggers coverage analysis + report
"Run test-maintainer to identify coverage gaps"

# Triggers persona validation + report
"Run persona-manager validation for all personas"
```

### For Agents

**Report Writing Guidelines:**
- Write to `.reports/{agent-type}/` directories
- Use consistent filename conventions
- Include timestamps in content (not just filename)
- Provide context for future reference
- Link to related files (source code, personas, debates)
- Track metrics over time for trend analysis

## Report Types

### Debate Quality Reports

**Purpose:** Assess historical authenticity, stylistic consistency, and engagement quality

**Frequency:**
- Per-debate: After each test debate
- Summaries: Weekly or monthly

**Key Metrics:**
- Authenticity score (1-10)
- Style adherence score (1-10)
- Citation quality score (1-10)
- Character consistency score (1-10)
- Engagement score (1-10)

### Test Coverage Reports

**Purpose:** Track testing progress toward production readiness

**Frequency:**
- Gap analysis: On demand
- Progress: After significant test additions
- Quality: Weekly

**Key Metrics:**
- Overall coverage percentage
- Per-module coverage
- High-value gaps identified
- Tests added this period

### Persona Quality Reports

**Purpose:** Maintain persona library health and accuracy

**Frequency:**
- Validation: After bulk updates
- Sync: After database synchronization
- Scorecards: Monthly for active personas

**Key Metrics:**
- Completeness score (1-10)
- Accuracy score (1-10)
- Usability score (1-10)
- Integration score (1-10)

## Retention Policy

**Active Reports:** Keep all reports for current development cycle

**Archive Strategy:**
- After major releases, archive to `archive/reports/vX.X/`
- Keep most recent 3 months of reports in active directory
- Preserve summary reports indefinitely
- Delete individual audit reports older than 6 months (unless flagged)

**Flagging Important Reports:**
Add `KEEP` to filename to prevent archival:
```
2025-10-20_aquinas-vs-sartre_KEEP.md  # Baseline quality example
2025-11-01_coverage-milestone-60percent_KEEP.md  # Major milestone
```

## Analysis & Trends

Agents should analyze report history to identify:
- Quality trends (improving or degrading)
- Recurring issues across multiple audits
- High-performing vs. low-performing personas
- Coverage progress toward goals
- Correlation between code changes and quality changes

**Example Trend Analysis:**
```bash
# Find all debate quality summaries
grep -r "Overall Score:" .reports/debate-quality/summaries/

# Track coverage progress
grep -r "Overall coverage:" .reports/test-coverage/progress/

# Identify low-scoring personas
grep -r "Average Score:" .reports/persona-quality/scorecards/ | awk '$NF < 7.0'
```

## Integration with Development Workflow

**Pre-Commit:**
- Review latest quality reports for blockers
- Ensure no critical issues flagged

**Pre-Deployment:**
- Require recent (< 7 days) aggregate quality report
- Minimum quality score threshold (7.0/10 average)
- Coverage target met (60%+ overall)

**Post-Deployment:**
- Generate baseline quality report for production personas
- Archive current reports to release directory
- Set quality baseline for next development cycle
